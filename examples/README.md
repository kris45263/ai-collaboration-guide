# 任务提示词的修改前后

这三组案例都要求 AI 根据用户材料，写一份可以交给另一个 Agent 的任务提示词。初稿和修订稿均来自实际子代理运行，没有手工改写输出，也没有要求初稿故意写得机械或较差。

| --- | --- | --- |
| 长对话交接 | [材料与来源](01-handoff/input.md) | [前后正文](01-handoff/comparison.md) |
| 开发协作方式 | [材料与来源](02-workflow/input.md) | [前后正文](02-workflow/comparison.md) |
| 旧文档处理 | [材料与来源](03-documentation/input.md) | [前后正文](03-documentation/comparison.md) |

## 生成过程

1. 将公开讨论中的情况整理成中文场景，写明来源和新增的任务设定。
2. 独立子代理 A 接收 input.md，完成其中编写提示词的任务，得到 before.md。
3. 另一个独立子代理 B 接收同一材料、before.md 和当时的协作文档，得到 after.md。
4. 将两份实际输出放在 comparison.md 中，并保留原始文件供核对。

两个阶段都不继承主聊天历史，不使用私人聊天案例；没有联网调查或操作来源中的真实项目。代理仍受宿主系统及工具环境指令影响。运行未显式覆盖模型与推理设置，具体型号未由工具返回。

## 给修订代理的请求

> 参考协作文档重新审视并修订初稿中的提示词，使其更准确地传达原材料中的意图、目标和协作需要。只输出可以发给另一个 Agent 的中文提示词。

运行还包含文件读取与写入范围的安排，以及只做写作、不操作真实项目的限制。用于交付的完整阶段说明见 [generation.md](generation.md)；机器相关路径留在本地运行记录中。

## 怎样阅读

先读用户材料，确认这个场景原本想处理什么，再看两版提示词。可以留意目标、假设、候选方案、必要约束和质量要求分别被怎样表达，不必以篇幅或排版变化判断效果。

本批保留全部三组结果，尚未评分或认定哪版更好。由于修订阶段增加了初稿、协作文档和一次修订机会，这些示例不能单独证明文档造成了哪些效果。它们也没有展示下游 Agent 收到提示词后的实际执行。

案例使用的是 2026-10-25 固定的早期文档。2026-10-27 发布准备中，正文去除了个人原话与特定经历，并调整为按情境使用的说明。输出没有重跑或人工改写，因此不能将它们视为当前发布版的实测结果。早期原文含个人材料，仅留本地；内容摘要值与生成条件供追溯使用。

案例输入是本项目对公开材料的概述或改编，非原作者逐字输入；来源链接保留在 input.md 中。第三方原帖全文没有打包进来。
